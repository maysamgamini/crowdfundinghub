# QA-001: Background loops have no exception guard, so one database error stops the whole host

| | |
|---|---|
| Severity | P1 |
| Owner repo | crowdfunding |
| Status | Open |
| Evidence | A2-F1, A5-F6 (see `qa-tickets/evidence/`) |

## Problem

`ModuleOutboxProcessor` and the webhook dispatcher loops have no top-level try/catch. A transient database error faults the `BackgroundService`, and the default host behaviour then stops the process. The other background services already guard their loops (hitechies-backend does too).

## Acceptance

A test makes the claim query throw once; the worker logs, waits and processes the next batch; the host stays up. Same for the webhook dispatcher.
