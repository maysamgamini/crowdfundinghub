# QA-007: GlobalExceptionHandler leaks raw messages, misses DbUpdateConcurrencyException, has no 503

| | |
|---|---|
| Severity | P2 |
| Owner repo | crowdfunding |
| Status | Open |
| Evidence | A2-F8, A5-F14 (see `qa-tickets/evidence/`) |

## Problem

Any `InvalidOperationException` or `ArgumentException` returns its raw message as a 400 (a pool timeout can surface as 400). `DbUpdateConcurrencyException` is unmapped (the known owner-delete 500 on CampaignUpdates is one case). There is no 503 with Retry-After for database overload, which hitechies-backend has.

## Acceptance

Unit tests for the handler: concurrency becomes 409, overload becomes 503 with Retry-After, internal messages are not echoed; the owner-delete race returns 409.
